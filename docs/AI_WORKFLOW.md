# AI Workflow

This document explains how AI was used while building Ajaia Docs. AI was used as a **development accelerator** — for scaffolding, drafting, and catching mistakes faster — not as a substitute for engineering judgment. Every architectural and product decision in this repo (what to build, what to cut, how access control works, how data is modeled) was made and verified by a human; AI did not decide scope, priorities, or tradeoffs on its own.

## AI Tools Used

- An AI coding assistant (Claude, via Claude Code) was used throughout, for architecture brainstorming, scaffolding files, TypeScript typing help, debugging build/lint errors, generating the automated test suite, and drafting this documentation set.

## Where AI Accelerated Development

- **Scaffolding boilerplate.** Generating the full set of shadcn/ui primitive components (button, dialog, dropdown-menu, select, tabs, etc.) by hand would have been mechanical, repetitive work; having them generated correctly the first time freed up time for the parts of the app that actually needed judgment calls (the authorization model, the sharing validation logic, the autosave debounce behavior).
- **Route Handler and RLS policy drafting.** Writing the first pass of the Supabase RLS policies and the corresponding Route Handlers side-by-side, so they could be checked against each other for consistency (does the API's manual permission logic actually match what the database policy allows?).
- **Diagnosing an RLS infinite-recursion bug from a symptom, not a stack trace.** After wiring up a live Supabase project, the dashboard silently showed "No documents yet" for an account that definitely owned a document. There was no visible error in the browser — the failure was a swallowed Postgres error inside a server component's data fetch. Rather than guessing, a throwaway Node script was written to run the exact same query as the app, directly against Supabase, outside of RLS (via the service-role key) and then again as the authenticated user (via the anon key). The second run surfaced `infinite recursion detected in policy for relation "documents"` — the actual error the app had been swallowing. AI helped connect that specific Postgres error code to its known cause (two RLS-protected tables whose policies each query the other) and to the standard fix (`SECURITY DEFINER` helper functions), which was then implemented and re-verified with the same throwaway script before touching the app again.
- **Diagnosing an ESLint flat-config crash.** `npx eslint .` started failing with `TypeError: Converting circular structure to JSON` from deep inside `@eslint/eslintrc`'s internals, with no indication of which file or rule caused it. Bisecting by hand (isolating `next/core-web-vitals` vs `next/typescript`) showed both extends failed identically, pointing at the shared compatibility layer rather than either config. AI helped identify that `eslint-config-next` 16.x already ships a native ESLint 9 flat config — the project's `eslint.config.mjs` was needlessly routing it through the legacy `FlatCompat` shim, which chokes on the plugin objects' intentional circular self-references. Importing the flat config directly instead of through `FlatCompat` fixed it outright, and lint then surfaced two genuine `react-hooks` issues (a ref mutated during render, and `setState` called synchronously in an effect body) that had been present but unchecked the whole time.
- **The markdown-to-TipTap converter** (`lib/markdown.ts`). A first draft of the line-based parser (headings, lists, bold/italic) was AI-generated, then manually reviewed for edge cases (nested lists were deliberately *not* supported, to keep it honestly scoped rather than half-implementing something more ambitious).
- **TypeScript friction.** Getting Supabase's generated join-query result types (e.g. `owner:profiles!documents_owner_id_fkey(...)`) to type-check cleanly against the app's own `DocumentListItem` types took a few iterations; AI helped narrow down the correct shape faster than manually reading Supabase's type inference source.
- **Debugging the Next.js 16 `middleware.ts` → `proxy.ts` rename.** The build initially warned about a deprecated convention; AI pulled the relevant doc from `node_modules/next/dist/docs` and confirmed the exact migration needed (file rename, function rename) rather than guessing.
- **Draft documentation.** First drafts of this file, `ARCHITECTURE.md`, and the README were AI-written from the actual code, then edited for accuracy as the implementation changed.

## AI-Generated Output Changed or Rejected

- The first draft of the dashboard's "create document" empty-state action used a brittle `document.querySelector(...)` hack to trigger a button click across components instead of properly lifting shared state. This was rejected during review and replaced with a small shared hook (`hooks/use-create-document.ts`) used by both the header and the empty state.
- An initial suggestion to add a full CommonMark-compliant Markdown parser (via a dependency) for file import was scoped down deliberately — the assignment only needs `.md` import to preserve basic structure (headings, lists, emphasis), not to round-trip arbitrary Markdown syntax like tables, footnotes, or nested blockquotes. Pulling in a full parser library would have been scope creep against the assignment's explicit "don't overengineer" instruction.
- Distinguishing "document not found" from "document exists but you're not authorized" was considered and rejected as a UX nicety, in favor of a single unified "access denied" message — a security decision (not leaking document existence to unauthorized users), not a shortcut.
- A login page redesign initially proposed (from a reference screenshot) included floating "Sarah" / "Mark" name-tag cursor bubbles next to document text, a "PDF" file-type icon, and a "Real-time Sharing" feature pill. All three were rejected and replaced before implementation: the app has no live-collaboration cursors, no PDF import (only `.txt`/`.md`), and sharing is not real-time. The mockup was adjusted to show only functionality that actually exists (static avatar initials instead of live cursors, a `.md` file badge, "Simple Sharing" instead of "Real-time Sharing") so the marketing page doesn't overstate the product.
- That same redesign's reference also included "Remember me" and "Forgot password?" controls. Neither is implemented, so both were left out entirely rather than added as non-functional UI.

## Verification Process

- **Every AI-suggested file was read before being accepted**, not just glanced at — particularly the RLS policies and Route Handlers, where a subtly wrong `USING`/`WITH CHECK` clause would silently break access control rather than throwing an obvious error.
- **Bugs were confirmed against the real system, not assumed fixed from reading the diff.** The RLS recursion fix and the ESLint config fix were both re-run against live infrastructure (the actual Supabase project, the actual lint command) after the fix, not just reasoned about — for the RLS bug specifically, a throwaway script re-ran the failing query as an authenticated user and printed the real result before the fix was considered done.
- **`npm run build`, `npx tsc --noEmit`, and `npx eslint .` were run after each major addition**, not just once at the end, so type errors and lint issues were caught close to the change that introduced them.
- **The automated test suite (`npm run test`) was run and its output inspected**, not assumed to pass — the priority test (`tests/permissions.test.ts`) was written to match the assignment's exact required scenario (owner creates → collaborator has no access → owner shares → collaborator has access → unauthorized rejected) so it verifies the real requirement, not just that some code path executes.
- **UI changes were screenshotted at desktop, tablet, and mobile widths and checked for horizontal overflow and console errors** before being called done, rather than trusting the Tailwind classes to behave as intended.
- No claim in this document, the README, or `SUBMISSION.md` describes AI as having made a product or architecture decision independently — all such decisions were made by the developer, with AI used to implement and validate them faster.
